# Monoprice Voxel GX Converter

Automates the painful part of 3D printing on your Monoprice Voxel: file format conversion and dimension verification.

## What It Does

Takes any STL, gcode, bgcode, GX, or G file and:
1. **Validates** the file extension
2. **Extracts dimensions** from the model
3. **Gates on size** - rejects anything that won't fit in your 150×150×150mm build area
4. **Converts intelligently**:
   - STL → gcode → GX (with your guidance for the slicing step)
   - gcode → GX
   - bgcode → gcode → GX (decodes the binary container in-process)
   - GX → stays as GX (ready to print)
   - G file → leaves as-is (for FlashPrint)

Binary gcode is also auto-detected by its `GCDE` magic bytes even when the file
carries a plain `.gcode` extension.

## Installation

```bash
# Make it executable
chmod +x voxel_converter.py

# Or run with Python directly
python3 voxel_converter.py <file>
```

**Requirements:**
- Python 3.7+ (no external dependencies - uses only stdlib)
- For STL slicing: FlashPrint 5 (free) or Cura (free)

## Usage

```bash
python3 voxel_converter.py model.stl
python3 voxel_converter.py sliced.gcode
python3 voxel_converter.py sliced.bgcode
python3 voxel_converter.py existing.gx
python3 voxel_converter.py file.g
```

## File Format Notes

**STL (Stereolithography)**
- Text-based or binary format describing 3D geometry
- Contains vertex coordinates that script uses to calculate bounding box
- Must be converted to gcode (slicing) before printing

**gcode**
- Plain text movement/printing instructions
- Script parses G0/G1 movement commands to extract max reach
- Specific to your printer settings (layer height, nozzle temp, etc.)

**bgcode (binary gcode)**
- PrusaSlicer / libbgcode container: `GCDE` header + typed blocks
- Script decodes it in-process (stdlib only): inflates Deflate blocks with
  `zlib` and unpacks MeatPack-encoded gcode, then reuses the gcode parser
- Heatshrink-compressed blocks are not supported - re-export with
  "No compression" or Deflate, or convert via PrusaSlicer first
- Decoding writes a plain-text `.gcode` sibling alongside the `.gx` output

**GX**
- Monoprice Voxel format: gcode with 4-byte binary header prepended
- Generated by FlashPrint 5 or this script
- **Ready to print** - copy to flash drive or send via WiFi

**G**
- Alternative gcode format 
- Script leaves unchanged (FlashPrint handles it)

## The STL → gcode Problem

STL is just raw geometry. To actually print it, it needs to be *sliced* - converted into printer-specific movement commands. This requires a slicing engine that knows about your:
- Layer height (yours: 50 microns)
- Nozzle size (yours: 0.4mm)
- Print speed (yours: 60mm/s)
- Material/temperature profiles
- Support generation

**Solutions:**

1. **FlashPrint 5 (Easiest)**
   - Free slicing software from Monoprice
   - Has Voxel profile built-in
   - Download: https://www.flashforge.com/support
   - Drag/drop STL, click "Export as gcode"

2. **Cura**
   - Free, open-source slicer
   - Download Monoprice Voxel profile from community
   - More features but steeper learning curve

3. **This Script (Future Enhancement)**
   - Could shell out to FlashPrint CLI if installed
   - Currently provides guidance and lets you handle slicing

## Dimension Checking

The script extracts actual model bounds:
- **STL**: Parses all vertex coordinates (supports both ASCII and binary STL)
- **gcode / bgcode**: Finds max/min X, Y, Z coordinates in movement commands
  (bgcode is decoded to text first)

Your Voxel bed: **150mm × 150mm × 150mm**

Models larger than this are rejected. You'd need to:
- Scale down in your CAD tool (Fusion360 is free)
- Print in multiple pieces
- Use a different printer

## Troubleshooting

**"No vertices found in STL file"**
- STL file may be corrupted
- Try opening in Fusion360 or MeshLab to validate

**"No movement commands found in gcode"**
- gcode file may be invalid or empty
- Check it opens in FlashPrint

**"FlashPrint conversion failed"**
- FlashPrint CLI not installed
- Use FlashPrint 5 GUI instead (just drag/drop the STL)

**"Model exceeds build area"**
- Use Fusion360 to scale the model down
- Or split into multiple parts to print separately

## Tips

- Keep your gcode files after converting to GX - gcode is human-readable for debugging
- GX files are gcode + header, so they're reversible (just remove first 4 bytes)
- FlashPrint 5 remembers your last-used printer profile
- Test dimension checking with a known-good file first to build confidence
